# Viewer and flow map

The viewer runs **in the host's process and language**, because live thumbnails need the real widgets (GTK widgets cannot cross processes). The behaviour below is the shared spec every language shell implements; the node coordinates come from the shared `layout.json`, so every language draws the same picture. Rust ships a complete viewer crate in the kit; other languages port it from this spec (a single C/GIR canvas library consumable by all bindings is the planned successor).

- **Story menu**: the left column is an `AdwNavigationView` drill-down (GNOME HIG "browsing": page header bars carry the back button; no tree widgets). Pages come from the pure `sidebar::pages`: root "Views" lists the views (display name from `states/<view>.toml` `title`, state count, `go-next`); a view page lists its flow nodes in journey order (a node without variants is a leaf); a node page splits the node and its variants by the first data dimension (axis order, `inventory.json`) whose value differs among them (`cells.json` assignments), one row per value in class order titled "<dimension>: <value>" from `states/<view>.toml` `[labels]` (fallback: humanized last segment of the axis path / class id with spaces) — a value held by one state is a leaf (state title as subtitle, state id in the tooltip), by several a further page split the same way; dimensions constant within a group get no level; a state with no assignment for the splitting dimension (stale or partial `cells.json`) is a plain leaf after the value rows, never a "?" branch, so every state is reachable exactly once. Search (`system-search-symbolic`; Ctrl+F anywhere shows the menu, returns to the root and focuses the entry) replaces the root list with flat results in place, so the entry stays visible while the query is refined. Programmatic selection (map click, `--story`, search hit) walks the pages to the leaf, selects it and shows it; exactly one leaf is selected across all pages, and re-activating the selected leaf reopens the preview. Viewer chrome strings are English; human names come from the host data (`title`, `[titles]`, `[labels]`).
- **One window, three columns**: an outer `AdwOverlaySplitView` (start) holds the drill-down story menu; an inner `AdwOverlaySplitView` with `sidebar-position = end` holds the flow map as content and the live preview of the selected state (width/theme presets, Events pane) as its collapsible end sidebar — both columns show/hide animated via toggles at the ends of the map's header bar (map controls centred), the preview also via its × button, and they overlay the map on narrow windows (`AdwBreakpoint`s: below 1100 sp the preview collapses into an overlay, below 720 sp the menu too; window minimum 360×294). Selecting a state in the menu shows the preview and highlights the state on the map (accent frame around the node; around its grid cell when the node is expanded; around the node when a variant is collapsed); a click on a node (or on a variant cell of an expanded node whose grid is already drawn — right after a `+N` click the grid is not hit until the relayout grows the node) selects that state the same way — the menu walks to it and the preview shows it; the cursor turns into a pointer over anything clickable. The map always opens fitted (whole journey in view). The menu opens on its first level with nothing selected and the preview hidden; `--story <id>` instead selects that state (menu walks to it, preview shown).
- **Flow map**: a custom widget with unbounded logical coordinates. Columns = longest-path layers from the roots over the DAG obtained by dropping back edges, so the journey reads left → right. Each view is a lane *segment* spanning its columns, labeled with the view display name (authored `title`, else the humanized view id); segments whose column ranges do not overlap share a row (first-fit), and the journey spine — the longest root-to-leaf path — is packed first so it runs along the top row. This keeps the map wide rather than tall. Collapsed nodes keep their plain box; an expanded node's box grows around its variant grid, and everything below moves away. Order within a slot is deterministic (`layout.json`). Labels never overlap: node titles are ellipsized to the node width in the strip under the thumbnail, the "+N" variant chip (accent) sits in the node's top-right corner (single click toggles the grid), and edge labels are opaque pills placed greedily along their curve at the first position that hits no node, title, header or earlier label (midpoint as last resort). Duplicate `(from, to)` edges are merged into one curve with the labels joined by ` / `; `kind = "self"` terminals are node data (`self_actions`), not edges; back edges and `back` targets are side arcs, **hidden by default** behind a header "Back edges" toggle.
- **Data variants**: a node with variants shows a `+N` chip. Clicking the badge expands/collapses the node's **inline variant grid**: the node's box grows to hold a 2-column grid of ~112x75 px thumbnails with their authored titles (fallback: the classes part of the state id) under each (8 px gaps), the layout is recomputed so every other node and cluster moves out of the way — nothing ever overlaps — and the transition is animated (~250 ms, ease-out). The relayout runs off the GTK main loop (`dot` rerun with per-node size overrides, honoring `SBK_DOT`; the builtin engine instead adds the grid height to the node's row and shifts the rows below); a generation counter drops stale results when several toggles race, and each new result animates from the geometry currently on screen. During the animation edges are drawn with the builtin edge geometry between the interpolated rects; the `dot` splines return when it ends.
- **Live thumbnails**: each node's real widget stays rooted and allocated at its preset width in an off-view container that is non-targetable and non-focusable; the canvas draws its `GtkWidgetPaintable` scaled with preserved aspect ratio. Zoom scales the drawing only, never the layout width. Dialogs and popovers are hosted in a dialog mode (embedded content) so they can be thumbnailed; a static snapshot fallback is allowed where embedding is impossible, marked as such.
- **Edges**: cubic Bézier `GskPath` curves with arrowheads; the action label is shown only for edges of the focused node.
- **Calm by default, focus on demand**: no outlines anywhere — nodes are rounded cards with a soft shadow, variant cells have none, label pills have no border. The **focus** is the hovered node, else the selected state's node (a variant focuses its node; pure `focus_node`). With a focus, its edges turn accent and show their labels, the node and its direct neighbours over the visible edges (`focus_set`) stay at full strength and everything else is dimmed to 30 %; without a focus edges are thin and unlabelled. Leaving the canvas drops the hover; the hover is recomputed from the last pointer position whenever the map moves under a still pointer (zoom, fit, relayout animation, new content).
- **Dot layouts**: when `layout.json` says `engine: "dot"`, geometry comes straight from the stored px values — nodes at their `rect` (hit testing included), edges as the stored Bezier chains with the stored arrowhead polygons, labels as opaque pills centred on `label_pos`, and each view's nodes grouped on a softly tinted rounded background (no outline) carrying the view display name in bold. `dot` runs with roomy spacing (`nodesep=0.9`, `ranksep=1.6`, 20 pt cluster margins) so nothing feels dense. Fit (also the initial view), the back-edge toggle and the "+N" chip behave exactly as in the builtin engine; an expanded node's `rect` covers its whole grown box (thumbnail, title strip, gap and variant grid).
- **Input**: drag or middle button pans; scroll (no modifier; wheel: one notch per step; touchpad deltas in surface px scaled at 25 px per notch, so gentle scrolling zooms gently; at most three notches per event) and pinch zoom around the pointer; `F` fits all (headers and arcs included); click selects a state (menu + preview), the "+N" chip toggles its grid.
- **Render signature** (`--check-render`): walk each story's widget tree — type name, visible, sensitive, label/text, css classes, child order — and hash it; build each story twice and compare (difference = hidden widget-local state).
