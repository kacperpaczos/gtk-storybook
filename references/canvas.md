# Viewer and flow map

The viewer runs **in the host's process and language**, because live thumbnails need the real widgets (GTK widgets cannot cross processes). The behaviour below is the shared spec every language shell implements; the node coordinates come from the shared `layout.json`, so every language draws the same picture. Rust ships a complete viewer crate in the kit; other languages port it from this spec (a single C/GIR canvas library consumable by all bindings is the planned successor).

- **Story list**: `AdwNavigationSplitView`; sidebar groups = views, rows = states; content = the live view inside an `AdwBreakpointBin` at the chosen width (360 / 600 / 900 / 1200; exact width: minimum = maximum) with theme System / Light / Dark from `AdwStyleManager`; an Events pane logs every action.
- **Graph first**: the flow map is the home page; the story list is pushed on top (header "States" button, node double-click, `--start list`, `--story <id>`). The initial view centres the root node and zooms it to ~80% of the canvas.
- **Flow map**: a custom widget with unbounded logical coordinates. Columns = longest-path layers from the roots over the DAG obtained by dropping back edges, so the journey reads left → right. Each view is a lane *segment* spanning its columns, with the view name above it; segments whose column ranges do not overlap share a row (first-fit), and the journey spine — the longest root-to-leaf path — is packed first so it runs along the top row. This keeps the map wide rather than tall. Collapsed nodes keep their plain box; an expanded node's box grows around its variant grid, and everything below moves away. Order within a slot is deterministic (`layout.json`). Labels never overlap: node titles are ellipsized to the node width in the strip under the thumbnail, the "+N variants" badge is a pill in the node's top-right corner (single click toggles the grid), and edge labels are opaque pills placed greedily along their curve at the first position that hits no node, title, header or earlier label (midpoint as last resort). Duplicate `(from, to)` edges are merged into one curve with the labels joined by ` / `; `kind = "self"` terminals are node data (`self_actions`), not edges; back edges and `back` targets are side arcs, **hidden by default** behind a header "Back edges" toggle.
- **Data variants**: a node with variants shows a `+N variants` badge. Clicking the badge expands/collapses the node's **inline variant grid**: the node's box grows to hold a 2-column grid of ~112x75 px thumbnails with their state titles under each (8 px gaps), the layout is recomputed so every other node and cluster moves out of the way — nothing ever overlaps — and the transition is animated (~250 ms, ease-out). The relayout runs off the GTK main loop (`dot` rerun with per-node size overrides, honoring `SBK_DOT`; the builtin engine instead adds the grid height to the node's row and shifts the rows below); a generation counter drops stale results when several toggles race, and each new result animates from the geometry currently on screen. During the animation edges are drawn with the builtin edge geometry between the interpolated rects; the `dot` splines return when it ends.
- **Live thumbnails**: each node's real widget stays rooted and allocated at its preset width in an off-view container that is non-targetable and non-focusable; the canvas draws its `GtkWidgetPaintable` scaled with preserved aspect ratio. Zoom scales the drawing only, never the layout width. Dialogs and popovers are hosted in a dialog mode (embedded content) so they can be thumbnailed; a static snapshot fallback is allowed where embedding is impossible, marked as such.
- **Edges**: cubic Bézier `GskPath` curves with arrowheads and the action label.
- **Dot layouts**: when `layout.json` says `engine: "dot"`, geometry comes straight from the stored px values — nodes at their `rect` (hit testing included), edges as the stored Bezier chains with the stored arrowhead polygons, labels as opaque pills centred on `label_pos`, and each view's nodes grouped in a subtle rounded cluster frame carrying the view name. `dot` runs with roomy spacing (`nodesep=0.9`, `ranksep=1.6`, 20 pt cluster margins) so nothing feels dense. Fit, the initial root-centred view at 80%, the back-edge toggle and the "+N variants" badge behave exactly as in the builtin engine; an expanded node's `rect` covers its whole grown box (thumbnail, title strip, gap and variant grid).
- **Input**: drag or middle button pans; Ctrl+scroll and pinch zoom around the pointer; `F` fits all (headers and arcs included); double-click opens the node full size and interactive in the story list.
- **Render signature** (`--check-render`): walk each story's widget tree — type name, visible, sensitive, label/text, css classes, child order — and hash it; build each story twice and compare (difference = hidden widget-local state).
